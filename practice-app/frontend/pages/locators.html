Common WAI-ARIA states & properties (aria-* attributes)

Per the WAI-ARIA 1.2 spec, these attributes let getByRole() filter by name, checked, pressed, expanded, selected, disabled, and level.

ARIA Attribute Purpose / Effect on getByRole()
aria-labelProvides the accessible name directly, used by { name: ... } option
aria-labelledbyReferences another element's text as this element's accessible name
aria-describedbyReferences the element(s) that describe this element (accessible description)
aria-checkedMatched by getByRole('checkbox', { checked: true|false })
aria-pressedMatched by getByRole('button', { pressed: true|false })
aria-expandedMatched by getByRole(role, { expanded: true|false })
aria-selectedMatched by getByRole('option'|'tab', { selected: true|false })
aria-disabledMatched by getByRole(role, { disabled: true|false })
aria-levelMatched by getByRole('heading', { level: 1-6 })
aria-hiddenRemoves the element (and its subtree) from the accessibility tree entirely
aria-currentIndicates the current item within a set (e.g. current page in nav)
aria-requiredIndicates a form field must be filled before submission
aria-invalidIndicates the current value of a field fails validation
aria-liveMarks a region as a live region ("polite"/"assertive") for dynamic updates
aria-haspopupIndicates the element triggers a popup (menu, dialog, listbox, etc.)

Accessible name computation sources (AccName spec order)

Per the AccName 1.2 spec, an element's accessible name — used by the { name } option in getByRole() — is computed from the first applicable source below.

Priority Name Source
1aria-labelledby (referenced element's text content)
2aria-label attribute
3Native HTML labelling (e.g. <label for>, wrapping <label>)
4placeholder attribute (host-language-defined fallback, e.g. for inputs)
5title attribute
6Subtree text content (visible text/descendant nodes flattened)
7alt attribute (for <img>/<area>)
